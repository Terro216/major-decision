## Поведение

В обычном режиме один из двух безопасных постановочных маршрутов LEFT/RIGHT
выбирается отдельным вызовом WebCrypto. Ответ выбирается независимо.
Каждый маршрут поддерживает YES и NO; cameraAt, путь шара, контакты,
вращение мишени и индикатор получают только маршрут. Геометрия, времена
контактов и радиус шара сохранены. Случайных смещений камеры через стенки нет.

Гарантия относится к маршруту камеры. Цветной импульс и буквы продолжают
показывать выбранный ответ по фильму. Сравнение пикселей также обнаруживает
отличия отражений далёких букв: LEFT около 2.9 s, RIGHT около 2.4 s.
Это не изменение камеры и не обещание скрыть все визуальные подсказки до
последнего кадра. Объекты не маскируются по времени ради такого обещания.

В `?review=1` FILM PAIR воспроизводит прежнее соответствие оригинальным
роликам. Переключатель ROUTE и `scenario=left|right` позволяют проверить
перекрёстные сочетания. В обычном режиме параметры URL не задают ни ответ,
ни камеру. Пауза, перемотка и WebGL-fallback сохраняют выбранную пару.

Под корпусом доступен RANDOM: LOCAL / RANDOM.ORG. LOCAL остаётся обычным
WebCrypto без внешних запросов. RANDOM.ORG получает 16 свежих целых чисел
0–255; `Math.floor(Math.random()*16)` выбирает одно. Нечётное означает YES,
чётное NO. Выбор индекса не делает источник «более случайным»: физическая
энтропия приходит от сервиса, Math.random только выбирает элемент.

Пока запрос выполняется, submit и изменение источника блокируются.
NEW QUESTION отменяет запрос и обнуляет поколение операции; запоздалый
ответ не запускает анимацию. Ошибка не подменяется локальной случайностью:
вопрос сохраняется, можно повторить запрос или выбрать LOCAL.
Один ответ и маршрут фиксируются до запуска; потеря WebGL их не меняет.

Внешний запрос содержит только постоянные параметры генератора. Вопрос
не передаётся, cookies и Referer отключены; вопрос и выбор режима не
сохраняются в storage. Сервис видит обычное сетевое подключение браузера.

## Проверенные бесплатные API

Исследование и сетевые пробы выполнены 2026-10-19 с big-one. Ключей и
новых зависимостей в приложение не добавлено.

| Источник | Доступ и результат исследования |
| --- | --- |
| [RANDOM.ORG HTTP API](https://www.random.org/clients/http/api/) | Атмосферный шум, HTTPS без ключа, CORS `*`; первичная проба 8 байтов и итоговый запрос 16 чисел из Chromium вернули 200. Бесплатная квота привязана к IP: максимум 1 000 000 бит, пополнение 200 000 бит в день. Выбран для приложения. |
| [drand](https://docs.drand.love/developer/) | Публичный криптографический beacon, без ключа. Два quicknet endpoint вернули 200 и CORS `*`. Это пороговая криптография, а не датчик атмосферного шума; зеркала публикуют одну цепочку. В приложение не включён. |
| [ANU Quantum Numbers](https://quantumnumbers.anu.edu.au/faq) | Квантовый источник, но новый API требует регистрации и ключа; не подходит для хранения секретного ключа в статическом frontend. |
| [NIST Beacon 2.0](https://csrc.nist.gov/projects/interoperable-randomness-beacons/beacon-20) | Публичные подписанные импульсы; текущий endpoint не ответил в 15-секундной сетевой пробе. В приложение не включён. |

Клиент соблюдает [пакетирование, последовательные запросы, длинный timeout
и проверку квоты](https://www.random.org/clients/): 16 чисел одним запросом,
timeout 120 секунд, проверка квоты при первом обращении и при новом запуске,
если прошло 10 минут; пауза 10 минут при отрицательной квоте/HTTP 429/503.
Фоновых запросов и автоматических повторов нет. User-Agent устанавливает браузер: старую
рекомендацию API вписать email в этот заголовок браузерный клиент выполнить
не может; вымышленный адрес не используется. HTTP API — старый интерфейс,
его доступность и квота не гарантируются приложением.

Самостоятельно создать новый корневой чат доступными инструментами нельзя.
NEXT_CHAT_PROMPT содержит переносимый текст; HANDOFF и VISUAL_REVIEW остаются
источниками фактического состояния. Коммит, push и публикация не разрешены.
